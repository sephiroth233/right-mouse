# RightMouse SDD 施工入口

将产品方案转化为可追踪、可实现、可验收的 macOS V1 规格包。

版本：0.1.0；日期：2026-09-22；面向开发与测试；方法：SDD（Specification-Driven Development，规格驱动开发）。本项目采用常见的 `spec → plan → tasks → evidence` 文件组织，不依赖某个 SDD CLI，也未安装或运行 Spec Kit。

## 1. 当前基线

当前已有原生宿主、FinderSync 扩展、共享核心、Xcode 工程和开发构建脚本。304 项核心、351 项宿主侧检查及 15 项隔离 APFS 双卷检查通过，最新证据见[来源隔离与竞争修复](../../specs/001-finder-core/evidence/EV-source-isolation-001.md)和[双卷验证](../../specs/001-finder-core/evidence/EV-real-volume-001.md)。真实 Finder 共享通信仍受签名授权限制，G0 与正式发布门禁未闭合；文档结构或夹具通过不代表完整应用验收。

范围承接 [原始设计方案](../design-plan.md)：新建文件、模板、复制路径/名称、剪切粘贴、复制/移动到、常用目录、Terminal/VS Code 打开、菜单配置、权限与诊断。图片工具、翻译、ZIP、云盘备用入口完整产品化列入后续版本。

## 3. 阶段门禁

| 门禁 | 条件 | 不通过时处理 |
| --- | --- | --- |
| G0：接入可行 | T001–T006 完成；真实 Finder、授权、冷启动和多实例命令链路验证 | 更新决策和计划；只继续不受影响的纯逻辑，不宣称原生入口可用 |
| G1：核心闭环 | 核心菜单、创建、复制路径、移动、打开应用可连贯使用 | 按失败用例修复，不开始正式打包验收 |
| G2：可靠性 | 故障注入、重名竞争、重复命令、性能、访问撤回和兼容矩阵通过 | 阻止发布候选，不以正常路径演示替代 |
| G3：交付 | 签名/公证/安装验证、文档、支持范围和未解决缺陷一致 | 只能交付明确标记的开发构建 |

门禁是工程证据检查，不意味着每一步都需要用户再授权。已批准范围内的常规开发可自主推进；改变产品范围、最低系统版本或破坏性行为时先更新规格并记录取舍。

## 4. 变更与交付

施工循环：选择一个未完成任务 → 确认需求和契约 → 实现最小可验收改动 → 运行关联用例 → 保存证据 → 更新任务状态。修复时引用失败用例；新增功能先新增规格。不得先勾选任务完成再补证据。

证据保存在 `specs/001-finder-core/evidence/`，记录系统/工具链、构建标识、步骤、预期、实际和对应检查入口；任务及用例关联见施工清单和机器可读映射。涉及用户路径的日志默认脱敏。已执行子场景与未执行系统验收分别记录，不用累计断言数量代替发布门禁。

文档冲突优先级：用户最新决定 → 工程约束 → 本版本需求规格 → 接口与数据契约 → 实施计划 → 任务说明 → 历史设计。出现冲突应修订相关文件，不能依赖阅读者自行猜测。
