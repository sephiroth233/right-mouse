## 输入与计时边界

每个场景包含 100 个模板描述、100 个收藏目录、100 个启用的应用描述，以及 10 个最近目标。最近目标中前三个目录与收藏重复，七个不同目录保留在每个复制到／移动到子菜单中；基准在每次计时之后验证最近子菜单数量及其叶子数量，确保确实执行了新规则。

最近目标由合法的共享快照 JSON 描述解码，使用固定合成路径与 UUID，不包含或制造安全书签，不访问任何真实目标目录。快照解码和校验发生在计时开始前，与 Finder 菜单回调使用内存快照的输入阶段一致。

100 动作是当前模型允许的压力配置：重复八种已知 commandType，使用唯一动作 ID、逆序 order 和 20 个分组；不是指默认 UI 有 100 种动作，也不是最终菜单只有 100 个节点。该配置包含 24 个复制／移动动作，各生成一个最近子菜单及 7 个最近目录叶子。默认 8 动作场景包含 2 个这样的子菜单。有效待移动快照包含 16 项、到期时间晚于固定测试时钟。

计时只包围非内联 wrapper 内的 `MenuPolicy.entries(snapshot:)` 调用，使用 DispatchTime 单调纳秒时钟。夹具构造、投影、解码、校验、输出树遍历、返回树释放和 JSON 编码不在计时区间内。规则内部的计算与临时分配包含在内。每个场景启动独立新进程；“首次”表示该进程第一次规则调用，并非清空操作系统或框架缓存。

## 环境、源码与复现

本轮 arm64、macOS 27.0（26A428）、SDK 27.0、Apple Swift 6.4，语言模式 Swift 5，部署目标 macOS 14.0；仍使用 Command Line Tools，不能据此声称 macOS 14 真机已测。各进程开始与结束热状态均为 nominal（0）。本轮没有独占机器、固定 CPU 或停止其他开发任务。

沙箱内硬件 sysctl 查询不可用，environment 保留真实错误；同机先前硬件记录保留在 [历史 hardware.json](../hardware.json)，未将其伪装成本轮重新采集结果。

编译前复制源码为固定快照，此后只编译该快照，避免并行开发改变编译输入。[source-hashes.json](source-hashes.json) 保存每个源文件的 SHA-256；[environment.json](environment.json) 同时保存编译器、构建基准提交、源码快照路径和实际二进制摘要。基准 Git HEAD 是构建时基线，工作区变更以源码摘要为准。

在仓库根目录执行，选择一个尚无证据的新目录：

本轮独立使用 `.build/menu-snapshot-benchmark`，未使用应用、Core 检查或 Host 检查的构建目录。脚本现在拒绝覆盖任何非空证据目录。

## 与历史报告的关系

[历史报告](../README.md)、[历史固定快照样本](../2026-09-23-snapshot/environment.json) 和首轮样本全部原样保留。本轮新增了最近目录去重及子菜单，也改为直接测共享快照入口；历史纯规则 P95 与本轮不是严格相同输入，不能据此单独认定性能回归或改善。本轮只新增三个场景各 100 次规则采样，不将历史与本轮累计成额外真实 Finder 验收。

三个场景本轮纯规则 P95 均低于 50 ms。完整验收仍需真实 Finder/NSMenu 构造、系统菜单弹出、后台 I/O 与目标发布环境证据。本轮未运行系统 I/O 追踪，也未宣称整个扩展进程没有后台 I/O。
