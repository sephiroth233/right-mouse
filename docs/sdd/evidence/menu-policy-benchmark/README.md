# MenuPolicy 纯规则性能证据

2026-09-23，本机实际 `MenuPolicy.entries` 的独立 `-O` 基准完成。三种场景各运行 100 次，最大规模场景包含 100 个配置动作，以及各 100 个模板、收藏目录和应用。第二轮固定源码快照的全部样本 P95 为 1.955 ms、4.104 ms 和 0.169 ms。

**这些结果只证明纯规则计算耗时。AC-027 的真实 Finder 回调、原生 NSMenu 构造、系统菜单弹出和后台 I/O 验收尚未完成；不得将本报告作为 AC-027 或完整 NFR-002 通过证据。**

## 配置与计时口径

当前配置模型允许至多 100 个 `ConfiguredAction`，要求 ID 唯一，但不要求 commandType 唯一。100 动作夹具将默认八种受支持动作循环展开：前四种各 13 个，后四种各 12 个；给每个动作唯一 ID、逆序 order 和 20 个分组。**这是模型允许的压力配置，当前设置 UI 默认只有八个分类，并不提供“新增动作分类”的功能。**

每个场景都使用 100 个有效模板描述、100 个收藏、100 个已启用应用描述。资源通过纯配置描述构造，不访问真实模板文件、不解析书签、不启动应用。较大配置展开后包含约 6300 个菜单树节点，不将“100 个配置动作”误写为“100 个最终叶子菜单项”。JSON 另行记录顶层节点数、全部节点数、可执行节点数与禁用节点数。

100 动作两个场景同时覆盖新建、文本格式、剪切、有效待粘贴状态、复制到、移动到、收藏、应用、排序和分组。1024 项场景跨 32 个父目录，覆盖实际规则的父目录集合构造和目标不可推断分支。8 动作场景保留正常默认分类数，帮助解释人工压力配置与用户默认分类的差别。

计时使用 `DispatchTime.now().uptimeNanoseconds`，只包围真实 `MenuPolicy.entries` 调用。Core 和基准程序分别以 `-O` 编译；独立 wrapper 标记 `@inline(never)`。每次计时结束后递归读取并校验输出树，保证实际结果被使用，而非测量可能被消除的空调用。夹具构造、配置校验、输出遍历、返回树释放和 JSON 编码均在计时区间外。规则内部的临时分配与处理仍包含在测量中。

每个场景启动独立新进程，直接采集 100 次，不预热，不删除离群点。P95 使用升序最近秩法：`ceil(0.95 × 100) = 95`，取第 95 项；表中的全部样本 P95 包含首次调用。后续 99 次的 P95 另外计算，同样取第 95 项；中位数取全部样本第 50 项。已独立校验六份 JSON 的 600 个原始样本和 P95。

“首次”仅表示新进程中完成夹具构造后的第一次 MenuPolicy 调用，**不表示操作系统或框架缓存已清空**。本次没有清空系统缓存、绑定 CPU、停止其他构建或占用用户机器，不能保证机器独占。每个进程开始和结束的热状态均为 `nominal`（0）。

## 环境与复现

硬件为 Apple M4，Mac16,13，24 GiB 内存，10 个逻辑核；系统为 macOS 27.0，build 26A428，arm64。编译器为 Apple Swift 6.4（swiftlang-6.4.0.34.1），SDK 27.0，语言模式 Swift 5，最低部署目标 macOS 14.0。当前使用 Command Line Tools，没有完整 Xcode；本次没有测 macOS 14 系统。

沙盒内 `sysctl` 被拒绝，因此环境文件保留真实的不可用结果；CPU 和内存信息通过获准的只读查询单独补充在 [hardware.json](hardware.json)。该文件只含型号、CPU、内存和核数，不含序列号、主机名或用户文件数据。

在仓库根目录运行：

```bash
bash scripts/benchmark-menu-policy.sh
```

默认输出位于 `.build/menu-benchmark/results/<UTC 时间戳>/`。也可以指定新的证据目录：

```bash
bash scripts/benchmark-menu-policy.sh docs/sdd/evidence/menu-policy-benchmark/<新运行标识>
```

脚本首先在 `.build/menu-benchmark/snapshots/<UTC 时间戳>/` 保存待编译源码快照，之后只编译快照文件；正在进行的其他开发不会改变该次编译输入。原始 JSON 的 `sourceSHA256` 对应此快照，`binarySHA256` 对应实际运行的程序。所有模块缓存、二进制和快照均位于独立 `.build/menu-benchmark`，不会使用其他测试或应用构建目录。

## 验收边界

本次三个场景的纯规则 P95 都小于 50 ms，但不能从中推出完整 Finder 菜单构建也达到 50 ms。真实验收还需要签名可用的 Finder 扩展、NSMenu 实体构造计时、Finder 回调场景、菜单弹出时延和后台 I/O 证据。源码可见该规则没有递归文件遍历、哈希或下载调用，本次没有另外运行系统 I/O 追踪工具，因此不声称完成整个扩展进程的后台 I/O 验证。
