# RightMouse 工程约束

规定 V1 的规格维护、文件安全、进程隔离和验收规则，作为施工时的共同约束。

版本：0.1.0；范围：原生独立分发的 macOS 应用；读者：开发、测试与代码审阅者。

## 1. 规格先行

每个对用户可见的功能必须关联需求 ID、任务 ID 和验收用例。协议/存储格式变化必须先说明版本兼容与迁移；破坏性变化禁止以小修复名义引入。`spec.md` 描述用户可观察行为，`plan.md` 描述实现方式；两者都不能以“与竞品一致”代替具体行为。

尚未验证的系统行为标记为“待实验”，附假设、步骤、通过条件和失败后的选择。技术文档示例不视为已实现 API。性能数值是测试目标，只有实际测量证据能证明达标。

## 2. 文件完整性

移动任务的核心不变量：未形成并验证目标副本，不删除源；发生冲突时不静默覆盖；用户取消不会触发额外删除。默认不覆盖、不合并目录、不永久删除。不引入提权守护进程解决普通读写失败。

文件身份校验和 no-clobber（目标存在即拒绝的提交语义）须贯穿计划、执行和恢复，不能只在开始时检查路径。恢复遇到无法证明的状态时保留两份或保留源，交给用户核对。对于外部进程并发改写带来的竞态，不声称可获得跨进程绝对原子性。

## 3. 原生接入与权限

Finder 扩展只构造菜单、捕获上下文和提交请求；批量文件操作、下载、图像计算和授权窗口交给宿主。不得依赖私有 API 或注入 Finder 进程。

目录覆盖、文件权限、自动化权限是独立机制。URL 字符串、App Group 成员身份、菜单可见性均不直接证明任意文件访问权。每次执行在实际访问进程检查权限；授权拒绝不触发更广泛授权的循环提示。[Apple 文件访问机制](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)

## 4. 可恢复执行

所有变更任务具备稳定请求 ID、逐项状态、取消语义和结果回执。已知成功的请求不重复执行；崩溃后不盲目重放具有副作用的阶段。界面超时表示状态未知或等待，不表示文件操作没有发生。

只在证据足够时自动恢复只读检查和结果归并；涉及再次写入、覆盖决策或删除源的恢复，进入用户可见的恢复流程。日志写入失败发生在副作用之前时必须停止。发生在副作用之后时标记待核对，不报完整成功。

## 5. 最小实现与验证

V1 使用一个宿主应用、一个 Finder 扩展和本地共享核心。后台执行器初期放在宿主内；在测得隔离需求前不增加独立 daemon、远端服务、账号或插件市场。主机离线仍能使用核心功能。

测试投入集中在数据安全、命令契约、权限和系统集成。纯文案/布局不要求镜像实现的单元测试；重名竞争、跨卷失败、命令重放和权限撤回必须有验证。测试只使用明确创建的夹具，禁止拿用户真实目录做故障注入。
