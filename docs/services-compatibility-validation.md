# Finder 系统服务兼容验证

日期：2026-09-23；环境：macOS 27.0（26A428），arm64。规格：[系统服务兼容入口](../specs/002-cloud-services/spec.md)。

## 已实现

五个固定 Services 使用系统传入的文件 URL，经白名单和边界校验生成现有宿主请求：TXT、Markdown、完整路径、终端、VS Code。新建只接受一个真实目录，不依据历史目录推测。模板、操作和打开方式检查沿用当前配置。

现代 file URL 和旧式文件列表都被校验；特别在 AppKit 自动转换旧式相对路径之前检查原始列表。拒绝任意文本路径、混合无效输入、远程 URL、未知操作、超过 128 项或 64 KiB 的 URL 输入。可能扩大沙盒能力的创建和打开服务声明 `NSRestricted`，没有取消系统对调用者的保护。

服务 provider 在应用启动阶段注册，进入服务回调即抑制延迟显示设置；同时识别系统服务启动 Apple event 标记。文件操作仍复用宿主异步执行、原有错误提示和短期回执清理，无新增历史或结果窗口。

## 实际 Finder 交互

先用独立只读探针验证 Services 在 iCloud 子目录空白处可见，调用时传入 1 个当前目录 file URL。探针仅记录分类、数量和是否目录，不读取文件内容。

再用最终宿主源码生成独立预览（`cn.rightmouse.ServicesPreview`），移除 Finder 扩展和 URL Scheme，使用独立数据目录。预览不连接产品 XPC、不发布菜单配置、不覆盖安装中的发行版。

| 场景 | 实际结果 |
| --- | --- |
| iCloud 根目录，对目录右键 | 系统「服务」菜单列出五个预览入口 |
| 服务冷启动，复制 iCloud 目录路径 | 剪贴板与预期目录精确匹配；新 PID 11908，activationPolicy=accessory，active=false |
| iCloud 子目录，空白处复制路径 | 五个入口可见，复制结果精确等于当前目录 |
| 本地夹具空白处，新建 TXT | 实际生成 0 字节 `未命名.txt`；回执 completed，无错误和任务结果窗口 |
| 后台服务调用后手动打开预览 | 设置窗口正常出现，显示「已复制 1 项」提示；手动入口仍可用 |

服务刷新期间曾短暂不显示整个 Services 子菜单；刷新系统服务缓存、重新进入目录后恢复。因此文档说明新安装可能需要重开 Finder 窗口或检查系统服务开关，产品不自动刷新全局服务缓存。

本轮没有在个人 iCloud 中创建文件、读取内容、下载占位文件或测试同步。云盘新建菜单存在且收到了正确目录，不等于云盘创建/同步已完成验收。终端与 VS Code 服务的真实应用启动留待使用者验收，现有适配器的行为未改变。
