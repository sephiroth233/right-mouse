## 1. 工程与模块

```text
RightMouse.xcodeproj/                  宿主与扩展 targets；shared scheme: RightMouse
Apps/RightMouse/                       App 生命周期、SwiftUI 设置和任务窗口
Extensions/RightMouseFinder/           FIFinderSync、菜单与请求提交
Packages/RightMouseCore/
  Package.swift
  Sources/RightMouseCore/
    Domain/                           菜单上下文、操作计划、错误和状态
    Menu/                             纯规则引擎，设置预览与扩展复用
    Templates/                        有效模板复制、命名与变量
    FileOperations/                   计划、复制、移动、恢复
    Integration/                      协议、书签和应用适配接口
  Tests/RightMouseCoreTests/           核心不变量与故障注入
Tests/RightMouseIntegrationTests/      宿主/协议/系统适配集成
Tests/RightMouseUITests/               必要的关键交互测试
Resources/Templates/                  内置真实模板
Config/                               Info.plist、entitlements、xcconfig
scripts/                              后续构建、签名检查脚本
```

模块边界：扩展可依赖 Domain/Menu/协议编码，不直接调用变更执行器；宿主负责配置写入、权限、持久化和执行。纯核心以协议注入文件系统、时钟、剪贴板和应用启动器，便于测试“磁盘满/权限拒绝/源变化”等情况；macOS 适配器单独做真实系统测试。

建议接口职责：`MenuPolicy` 计算可见/可用动作；`AccessResolver` 获取并释放访问范围；`OperationPlanner` 生成无副作用计划；`FileOperationExecutor` 执行并记账；`RecoveryCoordinator` 根据日志和文件身份判断下一步；`ApplicationLauncher` 适配应用。接口签名由实现阶段形成，语义以规格和契约为准。

## 2. 正常链路与通信

```text
Finder 菜单回调
  -> 捕获不可变上下文 + 缓存配置
  -> 构建菜单（不递归读文件）
用户选择动作
  -> 编码请求，原子发布到 App Group Inbox
  -> 显式唤醒已知宿主应用
宿主接收
  -> 验证版本、大小、时效、动作、引用和去重
  -> 持久记录 accepted -> 检查访问 -> 生成计划
  -> 询问必要冲突/授权 -> 执行 -> 写入逐项回执
  -> 轻量反馈 / 长任务窗口 / 恢复入口
```

配置文件由宿主单写，原子替换，带 `schemaVersion` 和递增 `revision`。扩展在初始化及变更通知后异步加载并校验到内存；菜单回调只读快照。通知只是刷新提示，不能承担唯一可靠存储。损坏配置保留问题文件，回退上一个有效快照或安全默认。

通信首选共享目录中的独立请求文件；接收端在启动和收到唤醒时扫描已提交请求，不读取 `.tmp`。主机内通过单执行器锁防止重复消费者；无副作用请求可独立处理，变更任务 V1 全局串行。详见 [协议](contracts/command-protocol.md)。若 G0 改为 XPC，保持 requestID、回执和失败语义不变。

只在合法菜单回调期间获取 Finder URL，避免异步调用时拿到 nil 或不同窗口选择。工具栏在监控范围外可能没有有效上下文，不能把工具栏可见解释为随处可执行。[Apple Finder Sync 约束](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Finder.html)

## 3. 文件操作机制

### 3.1 新建与模板

内置模板只读，导入模板保存到应用管理目录；修改显示名不修改模板字节。创建流程为验证模板和目标 → 生成候选名 → 写同目录临时文件 → 必要时同步 → 使用 no-clobber 语义提交 → 记录结果并在 Finder 定位。候选冲突重新生成名称，禁止覆盖已有文件。最终名称竞争测试必须使用两个并发创建者验证。

### 3.2 复制与移动

先做无副作用规划，展示顶层项目数和明确冲突。扫描仅在后台进行，遇到不支持的特殊文件不跟随处理。一个变更任务执行期间其他变更任务排队；只读复制路径、设置和取消保持可用。

同卷移动采用经过验证的 no-clobber 重命名/移动原语，并记录来源与目标身份。批量不是事务；一项失败不回滚其他已成功项。同卷撤销也需 no-clobber，原路径被占用或身份变化时拒绝。

跨卷移动流程：

1. 检查来源身份、目录关系、目标能力和必要元数据。
2. 写入阶段意图，建立目标卷上的任务专属暂存目录；不在用户源目录生成隐藏“剪切”文件。
3. 流式复制内容，普通文件计算 SHA-256；目录生成逐项清单，符号链接校验链接文本，不跟随目标。
4. 对目标重新读取校验；复核源内容/身份/必要元数据与计划一致。目录须核对条目集，防止遗漏中途新增文件。
5. 原子提交顶层目标，若目标已被其他进程占用则重新进入冲突处理，禁止覆盖。
6. 记录目标已提交。仅在源仍满足删除条件时执行最后检查和源清理；否则以 `sourceRetained` 结束。
7. 成功、部分成功、取消或需恢复均写回逐项记录。

“校验后删除”无法对恶意或持续并发写入提供全局锁。实现需要验证目标文件系统支持的身份检查、协调和安全清理策略；外部写入无法排除或源身份不可靠时保留源。尤其禁止对执行期间可能变化的目录直接递归删除。目录清理须对清单逐项核对并只移除已验证项，遇到新增/变化立即停止，最后只删除确认为空的目录。

目标卷暂存与最终目录处于同一卷；no-clobber 和持久化原语按平台实测选定，不把通用 `FileManager` 的单个便利方法当作整套事务。NSFileCoordinator 用于适用资源协调，但不能替代所有外部写入者的协作。[Apple 文件协调接口](https://developer.apple.com/documentation/foundation/nsfilecoordinator)

### 3.3 权限与生命周期

访问范围仅在执行时持有，所有返回路径释放。目录收藏与模板来源分别管理；模板复制完成后不再依赖来源持续授权。扩展覆盖范围与授权仓库分离。宿主非沙盒配置也必须处理系统隐私限制与文件系统权限，不能承诺获取任何目录写权。

需要用户操作的任务进入 `waitingForUser`，不持有文件句柄无限等待；恢复后重新验证。授权拒绝可取消该项；批次内其他不依赖该授权的项目继续。运行时禁用功能不强杀已提交的文件变更，取消按执行器状态处理。

## 4. 界面与诊断

设置页包括通用、菜单、新建文件、收藏、打开方式、文件操作、权限诊断。工具箱中的延期功能不展示不可用按钮。创建后默认定位新文件；V1 可使用命名弹窗，但不得依赖未验证的 Finder 键盘模拟。

任务窗口展示 `等待/处理中/等待你处理/部分完成/完成/已取消/需要核对`；进度扫描阶段用不确定进度，知道总量后再显示百分比。冲突弹窗显示源和目标，支持跳过、保留两份、对本批后续冲突应用同选择、取消剩余操作。

诊断日志只含请求 ID、命令、状态、耗时、错误码和脱敏资源标识。用户可主动复制诊断摘要。性能用 signpost 或等价测量记录菜单构建时间；不持续轮询全盘。操作日志写失败、命令长时间无回执、书签失效和扩展未启用均可定位到恢复步骤。

## 5. 阶段、验证与交付

| 阶段 | 任务 | 产物与退出条件 |
| --- | --- | --- |
| A 可行性 | T001–T006 | 环境、最小扩展、权限、冷启动、支持矩阵初稿；G0 |
| B 基础层 | T007–T011 | 模型/菜单/权限/协议/日志的可测试实现 |
| C 核心体验 | T012–T019 | 创建、剪贴板、收藏、移动、应用、设置、引导、恢复；G1 |
| D 完整验证 | T020–T021 | 端到端、故障与性能、版本矩阵；G2 |
| E 分发 | T022–T023 | 签名、公证、安装、文档、全部追踪证据；G3 |

初始工期仍采用产品方案的 14–23 个工作日，G0 后根据工具链、身份/元数据校验和实机资源重新估计；不是固定交付承诺。开发构建验证与正式签名验证分开。开发工程使用占位 bundle ID；T001 用真实开发者标识替换，不能把示例 Team ID 送去发布。

测试按风险安排：纯规则单测 → 临时夹具文件系统集成 → Finder 真机 → 故障注入 → 发布构建。所有阶段保留未测项，不把跳过计为通过。当前已有可编译的开发工程及独立检查脚本，使用方式见 [开工手册](quickstart.md)；已执行证据与尚缺的系统验收见[施工任务](tasks.md)。
