## 2. Given-When-Then 用例

自动测试主要验证规则和故障注入；表中标记“真机”的部分须使用真实 macOS 应用、Finder 与文件系统。每一行中的子场景都必须有实际结果，不能只运行最容易的一个。

| ID | Given：前置条件 | When：操作/注入 | Then：通过标准 | 层级 |
| --- | --- | --- | --- | --- |
| AC-001 | 扩展启用，普通目录已配置，文件/目录/多选夹具齐全 | 在空白、单文件、单目录、多选上右键 | 菜单和目标符合规格，源不被错误改变 | 规则+真机 |
| AC-002 | 两个 Finder 窗口、搜索结果与跨目录多选 | 打开菜单后切换窗口；在无唯一目录位置新建/粘贴 | 使用原上下文；无目标时要求选择，不写 home 等兜底目录 | 真机 |
| AC-003 | 可写空目录和 6 个内置模板 | 逐个创建并用相应方式读取 | 文件类型/字节有效，JSON 可解析，SH 无执行权限且未执行，Finder 定位准确 | 文件集成+真机 |

## 3. 兼容矩阵与测量

| 系统/架构/存储 | 计划状态 | 必需证据 |
| --- | --- | --- |
| macOS 14 / arm64 / 本地 APFS | 最低目标，未测 | 原生菜单、权限、核心闭环、冷启动 |
| macOS 27 / arm64 / 本地 APFS | 当前主机，只有环境核验 | 全部核心与故障/性能用例 |
| 实际发布时的其他支持系统 | 待确定 | 版本对应回归结果 |
| 外置 APFS、exFAT | 待测试卷 | 元数据、跨卷、取消、拔出和恢复 |
| iCloud、OneDrive | 调查范围，非 V1 完整支持承诺 | 菜单/上下文/占位文件边界 |
| Intel、网络卷 | V1 未承诺 | 另立覆盖后才能加支持声明 |

每次性能报告记录 CPU、内存、系统 build、Xcode/优化设置、配置规模、选择数量、样本数与分位数算法。100 个样本按升序最近秩 P95 取第 95 个；同时报告首次/冷状态，不能只删掉慢样本。失败样本记录原因，不纳入时用明示规则。

## 4. 门禁检查

- [ ] G0：EXP-01/02/03/05 的最低支持路径通过，EXP-04 有边界记录；R-002–R-005 已固化。
- [ ] G1：新建 Markdown → VS Code 打开 → 剪切 → 目标粘贴 → 冷启动重试路径通过。
- [ ] G2：AC-001–AC-029 必测子场景通过；AC-031 支持范围有实测证据；无数据丢失/静默覆盖问题。
- [ ] G3：AC-030 通过；需求、任务、用例、证据闭合；开发构建未冒充正式分发包。

如果缺少最低系统、签名或测试卷，记录具体未测项并限制交付声明。不得将 NOT_RUN 自动改为 PASS。任何数据丢失、错目录写入、静默覆盖、无授权执行都是发布阻断项，必须修复并重跑对应故障场景。
