## 1. 环境事实

本次通过只读命令获得：macOS 27.0（26A428）、arm64、Swift 6.4；`xcode-select -p` 为 `/Library/Developer/CommandLineTools`；`xcodebuild -version` 报告需要完整 Xcode。标准 `/Applications/Xcode*.app` 路径未匹配到应用，不排除其他位置已安装 Xcode。

工作目录尚未初始化 Git，未创建 Xcode 工程，也未检测证书、Team ID 或公证凭据。施工时先核对完整 Xcode 安装位置和支持当前系统的 SDK，再固定工具链。不得仅因 `swift --version` 成功就认为 Finder 扩展已能构建。

| R-002 | Finder Sync 作为普通目录原生入口 | Apple 提供上下文菜单能力，但定位并非通用 UI 定制；受系统行为影响 | API 已查，目标行为待 G0 |

| R-007 | 操作日志采用宿主单写、每操作版本化 JSON 快照 | V1 规模足够、便于检查；需原子替换/同步和崩溃窗口恢复设计 | 项目选择 |

所有实验使用用户明确创建的夹具目录。每个报告至少包含构建标识、签名方式、系统版本、输入、实际结果、失败日志和后续决策。普通本地目录实验是强制项；不可访问的云盘/外盘环境可记为未测，但不能列入已支持范围。

| 实验 | 关联任务 | 操作步骤 | 通过条件 | 失败后的处理 |
| --- | --- | --- | --- | --- |
| EXP-01 菜单上下文 | T003 | 在本地夹具的空白、单文件、目录、多选、两窗口中触发；点击前切换另一窗口 | 请求仍指向原点击对象，虚拟位置不写入错误目录 | 修正捕获时机/上下文规则；原生入口不可用则阻止 G0 |

## 4. 风险与后续取舍

全局串行执行可避免本应用内部冲突，但不能阻止其他应用改写文件。复制前后校验仍不能排除最后检查到删除之间的所有外部竞态；对身份不稳定的卷、活跃写入文件、无法保留必要元数据的目标，移动结束为“副本已生成，源保留”。阶段 T015 必须验证基于文件身份/句柄和文件系统支持的提交原语，不能只实现 `exists → copy → delete`。

App Group 请求队列需要在目标分发签名下复验；Development 签名可用不表示 Developer ID 构建必然可用。自定义 URL Scheme 是唤醒机制，不是可信命令来源；接收端仍检查实际队列记录。若最终改用 XPC，保留同一语义契约并增加调用者签名身份验证，不能简单把 JSON 传给任意进程执行。
