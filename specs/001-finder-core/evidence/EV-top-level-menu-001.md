## 1. 行为与配置

菜单管理新增“放到 Finder 一级菜单”列表，支持整组和具体操作；“其余菜单收进 RightMouse 子菜单”独立控制未选择项目。预览使用与 Finder 一致的 MenuPolicy。本机模式只展示受支持的内置项目，避免将自定义菜单预览误当作 Finder 的实际状态。

配置新增可选 topLevelEntryIDs，旧配置和旧菜单快照缺省为空。提升后的项目从原位置移除，空父菜单被清理；父子同时提升时各自显示且不重复。叶子补全操作标题，保留原执行参数、选中项上限、空白处禁用规则与未知目标处理。一级项目按选择顺序排列，Finder 决定与系统菜单的相对位置。

## 2. 本机同步

本机临时签名模式继续使用内置动作，通过 DistributedNotificationCenter 同步 compactMenu 和白名单内的一级菜单 ID。消息限 16 KiB，仅含版本与两项展示偏好，拒绝未知字段、未知版本、重复和非内置 ID。扩展缓存于自身 UserDefaults，启动和每 5 秒请求主应用刷新；主应用启动和设置保存时主动发布。菜单回调不读取磁盘。

该通道没有来源认证，因此不能传递执行指令、路径、书签或自定义应用。它仅改变内置菜单展示；文件操作仍走已有校验和确认，收到通知不会执行任何文件操作。共享模式继续通过 App Group 中的菜单快照同步。

## 3. 检查与真机证据

新增 23 项检查覆盖叶子、整组、父子同时提升、空菜单清理、禁用动作、上下文与数量约束、旧配置/快照兼容，以及本机消息白名单和大小限制。核心全套 364 项通过，宿主全套 408 项通过。核心检查首次在受限环境中因文件协调服务失败，允许系统文件协调服务后重跑同一二进制通过。

通过原生应用工具在菜单管理勾选“新建 文本文档”和“复制完整路径”，开启其余菜单收起。09:47:55 的真实扩展日志先后记录一级项目数 1、2。Finder 对 source.txt 的实际右键树显示下列同级项目：隔空传送、新建 文本文档、复制完整路径、RightMouse、RightMouse 设置、MacZip 菜单；TXT 和完整路径已从 RightMouse 子树移除，其余操作保留。

取消“复制完整路径”的一级勾选后，再次右键，Finder 顶层仅保留新建文本文档；完整路径回到 RightMouse / 复制路径与名称子菜单。随后重新勾选，最终为用户保留两项常用操作便于验收。本次不触发文件操作，不修改测试源文件。

退出主应用、重新构建并登记扩展后，在主应用仍关闭时再次打开 Finder 菜单，两项一级操作均存在，验证扩展从自身缓存恢复。重新启动最终主应用后，菜单管理两项勾选及紧凑开关仍保留，预览与 Finder 一致。

最终开发构建和签名检查通过，ZIP SHA-256 为 d703609733825b5a67098237dc3bac2e0025fdaf1e99abf2d15613f7add37ef8。SDD 验证通过：32 个 Markdown 文档、20 个需求、23 个任务、31 个验收案例、3 个 JSON Schema、22 个文档探针。

## 4. 验证边界

真实菜单层级通过 Finder 可访问性树验证；工具未能获取 Finder 菜单截图，不将像素级外观记为通过。当前本机同步范围不包含自定义模板、应用、收藏、排序和分组；正式共享模式的对应能力仍需正式签名环境验收。新增功能不解决此前逐次文件操作确认问题，也不将完整 AC-015 系统矩阵标记通过。
