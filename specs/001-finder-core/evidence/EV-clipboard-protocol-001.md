## 1. 发现的问题与行为修复

原先部分粘贴结束后会重新写入剪切标记；如果用户在长任务期间复制了其他内容，这一步可能覆盖较新的剪贴板。现在只有新的剪切动作声明剪贴板，剩余项目更新只写共享摘要，不重新写标记。活动会话同时匹配 token、剪贴板 changeCount 与 24 小时时效；即使后来重新写回旧 token，也不能恢复旧会话。

原先文件传输已保存结果后，更新剪切摘要若失败，会进入外层异常处理，可能把已完成的文件任务改报为失败。现在这类故障只使剪切会话失效并显示单独错误；已保存的逐项结果和回执继续保留，成功移动的文件不会被错误地报告为未执行。

新的剪切必须完成快照及最终任务记录的写入。快照失败，或标记发布后最终账本写入失败，都会使本次新建 token 失效。异常处理只针对本次创建的会话，避免把另一个旧会话当作本次副作用。复制文本或剪切标记时也检查实际剪贴板写入是否成功，不忽略失败返回值。

生产默认仍使用系统通用剪贴板；测试可注入独立命名剪贴板与待移动会话时钟。该时钟只影响剪切有效期，不改变请求的 120 秒接收期限、诊断时间或文件操作时序。

## 2. 剪贴板与文件检查

新增 `ClipboardHostChecks` 33 项检查，调用真实 HostController、文件引擎及系统命名剪贴板服务。每次使用 NSPasteboard.withUniqueName，完成后释放；不读取或改写用户的通用剪贴板。来源、目标、损坏快照和权限故障均限制在 UUID 隔离目录。

| 检查组 | 已观察结果 |
| --- | --- |
| 四种路径格式 | 中文、空格、单双引号、换行、emoji、.env、a.tar.gz 及 shell 元字符的多选结果正确；来源字节保持不变 |
| shellPath 实际参数解析 | 将真实复制文本交给 /bin/sh 的位置参数与 NUL 分隔输出，结果逐字节等于原始路径；文件名中的 touch 片段未执行 |
| 新剪切及替换 | 来源字节、权限及 mtime 不变；新 token 替换旧选择；旧 token 拒绝移动，成功项从列表移出 |
| 剪贴板改写 | 独立剪贴板被模拟外部写入后失效；旧 token 即使再次写回也失效；部分移动后保留较新的复制内容 |
| 到期与重启 | 注入时钟验证到期瞬间拒绝；释放并重新构造宿主后旧会话不能恢复 |
| 快照发布失败 | 剪切报告失败后，旧标记仍不能使来源被移动 |
| 最终账本写入失败 | 在标记发布后将夹具 Commands 目录设为 0500，任务进入核对且会话失效；恢复 0700 后旧 token 仍不能移动文件 |
| 部分完成后更新失败 | 成功目标和跳过来源的字节完整；原逐项成功/跳过回执保留，单独报告剪切列表更新失败 |

首次回归发现夹具从 ISO 8601 秒级摘要读取截止时间，却与内存中的亚秒时间比较，导致测试在真正截止时间之前执行。已把注入时钟固定到整秒，使同一截止瞬间精确可比；没有通过放宽生产有效期来通过测试。

这些结果证明进程内真实宿主和独立系统剪贴板服务的行为。外部应用复制通过测试向同一独立剪贴板写入来模拟，没有操纵真实第三方应用；重启是释放并重新初始化宿主，不是强杀整个可见应用。AC-006、AC-007、AC-008 的 Finder 入口及相关系统流程继续未完整验收。

## 3. 协议接收检查

协议检查从 19 项增加到 33 项，新增 14 个断言。构造顶层 JSON 键明确逆序、包含额外空白的合法请求，先确认原始字节不同，再通过 InboxStore 读取、canonical enqueue 重投和 CommandLedger 接受。相同语义只接受一次，摘要一致。

未知版本、未知嵌套字段、畸形 JSON、超过 1 MiB 的请求在接收器被拒绝；过期及超过未来时间窗口的请求可完成结构解码，但在账本接收时被拒绝。每个拒绝用例都检查该 requestID 没有账本记录。原有检查继续覆盖未知顶层字段、布尔值冒充版本、非法动作、选择数量、重复引用和 URL 限制。

AC-025 指定的正常/畸形、未知字段/版本、超限、过期、未来时间及键序/空白变化均已有协议接收证据，标记 PASS。这里的接收链是 InboxStore → RequestValidator → CommandLedger；证明结构解析与执行接收许可分离，不声称真实 Finder 的跨进程投递通过。AC-023 与 AC-026 的系统唤醒、授权等部分仍独立保留未测。
