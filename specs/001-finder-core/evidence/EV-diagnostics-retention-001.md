## 1. 行为与约束

宿主记录启动、配置保存、任务接受和结束、恢复核对、重试与撤销请求。事件 API 只接受时间、组件枚举、随机请求 ID、动作枚举、状态与错误码，不接收任意错误正文、路径、文件名或书签。设置页提供主动导出 JSONL；导出重新编码经过验证的白名单字段，不复制原始日志字节。损坏、未来版本或未来时间的记录会过滤；未知附加字段不会进入导出。日志失败只增加问题计数，不阻断文件操作。

事件保留期限为 7 天，活动日志容量为 10 MiB，先达到的限制生效。原子替换期间最多另有一份有界暂存文件。目录权限为 0700、文件为 0600；逐级目录描述符访问拒绝符号链接及不可信文件。macOS 的 Foundation 会把部分 `/private/tmp` URL 收缩为 `/tmp` 别名，宿主因此使用 Darwin `realpath` 取得已准备应用根目录的物理路径，后续诊断目录继续执行不跟随链接的检查。

宿主启动时在接受任务前执行记录清理。请求创建时间和终态回执更新时间均早于 30 天的记录才进入候选，并且需要请求、回执及操作侧车一致。重试任务按关联组件处理；任何成员近期、非终态、缺失或不确定，则整组保留。带撤销记录、旧暂存引用或缺少完整侧车的任务继续保留。无法可信解析的 Followup 可能隐藏单向重试关联，因此会停止整轮清理。清理只删除经过验证的应用记录，不访问来源、目标或暂存内容，详见[保留策略检查](../../../Config/validation/operation-retention-2026-09-23.md)。

审查发现普通“侧车先删、命令最后删”顺序仍可能先丢失重试关联。修复后按普通证据、保存重试关联的父 Followup、Commands 三阶段删除。关联被删除前，每个成员的回执均已删除；中断后的剩余成员不会被误判为证据完整的独立任务。对双成员组件的全部 7 个中断位置逐一注入失败，并复跑清理确认剩余记录继续保留。

文件引擎成功清理暂存后才清空其日志引用；若暂存 inode 被替换，引用和新占用者均保留。权限、空间、卷状态、来源变化和目标冲突使用独立失败码。宿主逐项回执保留该错误码及可重试属性；不可重试项不显示重试按钮，直接调用重试回调也不能入队。旧结果没有新增字段时保留兼容读取及原有身份核对。

配置读取、保存及 Finder 扩展统一引用 `ConfigurationStore.maximumBytes`，上限 8 MiB。合法的 2–8 MiB 配置可以由两端读取；超过上限的保存被拒绝且不改变旧字节或 revision。

## 2. 检查结果

| 检查 | 结果 | 覆盖范围 |
| --- | --- | --- |
| 核心完整回归 | 226 项通过 | 原有 150 项、失败码 21 项、诊断 35 项、暂存证据 9 项、配置容量 11 项 |
| 宿主完整回归 | 244 项通过 | 原有 168 项、诊断与失败码宿主 20 项、保留策略 56 项 |
| `scripts/package-app.sh --development` | 通过，退出码 0 | 宿主与嵌入扩展、开发签名结构 |
| SDD 文档检查 | 通过 | 21 份 Markdown、20 需求、23 任务、31 验收用例、2 份 schema、17 项文档正反例 |

权限拒绝、缺失来源、替换暂存 inode 和记录清理使用真实临时文件。磁盘满及卷断开的错误码通过阶段注入验证，不能作为真实磁盘故障验收。诊断检查包含附加敏感字段、损坏 JSON、未来记录、容量与时间边界、硬链接与符号链接，以及并发追加。宿主检查确认日志目录被替换为链接后文件操作仍能完成、链接目标未修改且无法导出其内容。

测试使用随机临时目录。文件协调及安全书签需要系统服务，相关检查获准在能够访问这些服务的环境运行。保存面板、导出按钮的真实点击、VoiceOver 与视觉效果尚未完成 UI 验收。

本轮再次尝试通过原生 UI 工具选择开发 App：按路径返回 `cgWindowNotFound`，应用列表能确认进程正在运行，随后按 bundle ID 读取返回 `Sky Computer Use native pipe closed before response`。没有取得窗口截图或可操作的可访问性树，因此不把进程运行或编译成功作为液态玻璃视觉及窗口居中验收。
