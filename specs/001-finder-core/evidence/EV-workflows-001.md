## 1. 已实现的行为

冲突选择可只处理当前项目，也可将保留两份或跳过应用于本批后续冲突。选择不会写入全局偏好，也不会泄漏到下一任务。弹出 sheet 前先保存等待状态；返回后先保存继续状态，再由引擎复核来源与目标身份。记录写入失败时停止后续工作。取消、窗口不可用或 15 分钟等待到期均保留已完成项并取消剩余项目；重启后旧等待进入核对，不重新执行。

最近目标最多保存 10 项，包含安全书签及设备、inode、目录类型。手动选择或成功使用将记录移到首位，重复目录按身份合并。旧 schema 1 配置缺少该新增字段时按空历史读取，原有设置保留；最终编码超过 8 MiB 时不写入。最近目标页提供选择、检查、修复、移除与清空，后两者不删除用户目录。Finder 菜单与操作台使用同一保存记录 ID，未知、删除或损坏引用不按路径提示降级。

VS Code 的单文件、单目录和同目录多文件维持各自语义；跨目录或混合目录选择先请求一个项目目录，只交付该目录。选择取消或返回非法对象不启动应用。实际应用 bundle 与配置及适配类型在启动前核对；自定义应用的提示只说明已交付 URL，不声称应用已经处理内容。

## 2. 实际验证与修正

| 命令或检查 | 实际结果 | 证明范围 |
| --- | --- | --- |
| `scripts/check-core.sh` | 150 项通过，退出码 0 | 原有 129 项及新增 21 项最近目标、配置兼容与容量检查 |
| `scripts/check-host.sh` | 168 项通过，退出码 0 | 153 项真实 HostController 夹具断言，加 15 项纯打开方式规划断言 |
| `scripts/package-app.sh --development` | 通过 | 当前宿主、嵌入扩展实际编译，签名结构与开发存储标志验证通过 |
| `python3 Config/generate-project.py` | 完成 | Xcode 工程包含 15 个应用源码、1 个扩展源码及 5 个 XCTest 文件 |

宿主侧的组成是：原有 59 项、43 项冲突处理、21 项最近目标、15 项打开规划、30 项打开方式宿主检查。文件操作使用真实引擎和随机临时目录；应用打开只替换最终 OS 启动边界，以避免测试启动用户应用。必要的安全书签和文件协调检查在获准访问系统服务的执行环境中运行。

新增负例证明：本批策略不影响下一任务；等待中替换来源父目录或目标目录后不生成编号副本；等待日志拒绝写入时不弹出选择也不执行后项；最近目标的删除、未知 token、损坏书签均拒绝；失效目标不阻止针对已选文件的无关操作；配置容量拒绝保留原字节。

审查发现空选择的目录打开曾忽略 container 的保存记录 ID。修复后，给出“记录 ID 指向 A，但路径提示指向另一个现存目录 B”的请求，宿主仅交付书签解析出的 A 一次，并按真实目录身份确认没有交付 B。空选择的路径复制也使用相同解析入口。

回归过程中另修正了新夹具的两处错误：旧的环境变量启动改为显式存储注入；Foundation 的 `/var` 与 `/private/var` URL 表示差异改用实际目录身份核验。没有为通过测试放宽生产环境的存储或书签限制。

## 3. 产物与验收边界

开发包位于 `dist/RightMouse-0.1.0-development.zip`，本轮 SHA-256 为 `9508e14d7b30f1d7b5bcc5319ab3bed4ea3cb5ed1d6713c80030b26301ce1198`。源码仍以 macOS 14 为部署目标，当前实际构建及夹具运行环境为 macOS 27 / arm64 / Command Line Tools。

冲突超时检查注入超时结果，没有真实等待 15 分钟；sheet 点击、关闭、键盘与视觉行为仍需真机 UI 验收。最近目标的 Finder 风格命令由真实宿主处理，但没有通过真实 Finder 扩展投递。打开方式的 OS 边界被替换，不能据此宣称 Terminal 或 VS Code 真机体验通过。跨卷、磁盘满、卷断开、最低系统和有效发布签名仍有独立未测项。
